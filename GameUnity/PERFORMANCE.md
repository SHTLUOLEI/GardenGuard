# 性能题：怪多时一打就卡

## 现象和证据

正常模式玩起来没问题。压力模式下怪一多，炮塔连续击杀或者技能一下砸中一大片的时候，画面会一顿一顿的，手机也明显发烫。

优化前的包在抖音开发者工具的性能测试里，平均帧率 49.18（目标 60），卡顿率 0.13%，Unity Heap 184 MB，Heap 涨了 2 次。

为了找到具体是哪里卡，我在 Editor 里给新旧两版代码喂同一份固定输入（512 只敌人、64 个水花、带 HUD 和飘字，预热 20 次、采样 300 次，机器是 i9-12900H），看到这几件事：

- 连续普攻 120 帧，有 114 帧处在顿帧冻结里；
- 64 个水花各自用一个 MaterialPropertyBlock，每个都会打断合批；
- 512 只敌人时，表现层刷新一次要 1.854 ms；
- 每次击杀都会新建一个分数弹跳的 Tween，每次命中都单独 PlayOneShot 一次。

## 原因和改法

最主要的原因其实不是性能不够，是顿帧。顿帧本来是给技能做打击感的，结果普攻也会触发。压力模式下普攻命中太密，画面几乎一直在被冻住，看起来就是一顿一顿的。我改成普攻不再顿帧，只有技能命中保留 45 ms 的短顿帧，规则时间、伤害和排序都不受影响。

剩下几处是实打实的开销，顺手一起处理了：

- 水花的播放进度改成写进顶点 alpha，所有水花共用一份材质，重新合成一批；
- 敌人的 Transform、精灵宽度、状态和排序值都缓存下来，深度排序改成在上一帧的顺序上做增量调整，不再每帧全排；
- 分数弹跳复用同一个动效时钟，不再每次击杀都新建 Tween；同类命中音效 50 ms 内合并成一次；
- 索敌原来是 LINQ 排序，改成线性扫描。

另外还删掉了一个"单帧超过 0.5 秒就自动暂停"的逻辑。加载时的尖峰会误触发它，压力模式下会莫名其妙弹出暂停页。切后台、失焦和手动暂停都保留了。

## 结果

Editor 同一份输入、同一台机器的对比：

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 表现层刷新（512 敌人） | 1.854 ms | 0.397 ms |
| 512 敌人 + 64 水花 + HUD/飘字 | 0.517 ms（p95 0.646） | 0.389 ms（p95 0.504） |
| 120 帧普攻里被顿帧冻结的帧 | 114 | 0 |
| 水花用到的属性块 | 64 | 0 |
| 索敌（512 敌人） | 96.5 µs | 9.4 µs |

真机是 iQOO 9，开发者工具真机调试，压力模式完整玩一局：

| 指标 | 优化前包 | 第二轮包 | 当前包 |
|------|----------|----------|--------|
| 平均帧率 | 49.18 | 50.70 | 48.55 |
| 卡顿率 | 0.13% | 0.05% | 0.07% |
| Unity Heap / 增长次数 | 184 MB / 2 | 184 MB / 2 | 128 MB / 0 |

当前包我还用游戏里的性能面板在压力模式下采了 60 秒（1080×2400，目标 60 帧），同一个包、同一台手机、同一段时间里只切换特效档位，两档各跑一次：

| 指标 | 完整档 | 简化档 |
|------|--------|--------|
| 帧耗时 平均 / P50 | 17.4 / 17.0 ms | 17.5 / 17.0 ms |
| 帧耗时 P95 / P99 / 最长 | 23 / 40 / 111 ms | 24 / 40 / 152 ms |
| 超过 33 ms 的帧 | 76 帧（2.2%） | 80 帧（2.3%） |
| 同屏敌人峰值 | 288 | 298 |
| 托管堆增长 / GC 次数 | +0.66 MB / 0 | +1.05 MB / 0 |
| HUD 平均 / 最长 | 0.37 / 56 ms | 0.47 / 74 ms |
| Battlefield 平均 / 最长 | 0.62 / 31 ms | 0.65 / 44 ms |

我从这些数里得出的结论：

卡顿率从 0.13% 降到 0.07%，近 300 只怪同屏的时候 60 秒内一次 GC 都没有，普攻也不会再把画面冻住，一顿一顿的感觉基本没了。

平均帧率看起来没涨（49.18 到 48.55），但开发者工具这个数统计的是整局，包括首页和加载。战斗中的 P50 是 17.0 ms，跟 60 帧的 16.7 ms 很接近，大部分帧其实已经跑满了。

两档特效的帧耗时几乎一样，说明这台手机上特效不是瓶颈。飘字耗时从 0.09 降到 0.01 ms，档位确实生效了，只是对帧率没什么影响。这组档位对比是糖果水特效改版之前测的，改版后还没重测。

Heap 从 184 MB 降到 128 MB、不再增长，这主要是 WebGL 内存配置（固定 128 MB）和资源压缩的功劳，不是这次战斗代码改出来的。

还没解决的是偶发的长帧：大约 2% 的帧超过 33 ms，最长 111 到 152 ms。HUD 平均不到 0.5 ms，单帧却能冒到 56 到 74 ms，应该是偶尔的尖峰而不是持续负载。我怀疑是连击和分数文字变化时字体网格重建，也有可能是 WebGL 下计时被浏览器调度打断了，还得用 Profiler 再确认，这次没处理。

## 代价和限制

先说明改了哪些配置。第二轮把全局帧率上限从 120 改成了 60，还压缩了首页背景（只针对 WebGL，最大 2048）；后来又调过 WebGL 内存和包体。所以三个包的构建配置并不完全一样，真机上的差异不全是代码优化带来的，严格的单变量对比只有 Editor 那一组。敌人数量、伤害、刷怪节奏和分辨率都没动过；特效档位只在档位对比时切换，其他测试都是完整档。

改动本身的代价：普攻没了顿帧，打击感弱了一点；同一帧里的命中音效被合并了，怪多的时候声音层次少一些；水花 Shader 要同时支持顶点参数和材质参数两条路，我用测试保证了两边画出来一样。

测量上的限制：

- Editor 基准只能看 CPU 和顿帧，看不到手机 GPU、WebGL 桥接、音频解码和发热降频。
- 优化前那份真机报告当时没记下测的是哪个场景、怎么玩的，也没有 P95/P99，跟现在的压力模式整局不能保证负载完全一样。
- 真机数据都是开发者工具真机调试下测的，调试连接本身也有开销。
- 只有 iQOO 9 一台手机，没测低端机和 iOS，也没有长时间的发热数据。
